# Evaluation Harness

[한국어](../ko/evaluation-harness.md) | [English](../en/evaluation-harness.md)

## Purpose

LLM/RAG outputs can vary, so evaluate them repeatedly with a fixed question set.

## Evaluation Set Structure

As in the original `law_research_assistant`, evaluate retrieval recall separately from answer quality.

- `harness/questions.json`: a v1-style API integration evaluation set covering question analysis, retrieval, citations, status, and trace linkage together.
- `harness/answer-quality-v2.json`: a v2-style answer-quality set that assumes retrieval results are supplied and checks Korean responses, citations, forbidden copy, decisive wording, and valid article numbers.

## First-Stage Evaluation Metrics

| Metric | Description |
| --- | --- |
| Citation Required | A `status=OK` response must have a cited article |
| Retrieval Recall | At least one expected law/article pair must appear among citations |
| Vector Hit Threshold | Normal questions must meet the minimum vector-hit count |
| Insufficient Handling | Ambiguous questions return `INSUFFICIENT_INFO` |
| Metadata Handling | Effective-date/law-number questions are answered from law metadata |
| Revision Compare | Comparison questions link target articles and earlier revisions through citations/historicalEntries |
| Log Safety | Search logs focus on hashes, lengths, and previews |
| Agent Trace | Store stage traces and verify their order by requestId in scenario scripts |
| Failure Audit | Missing indexes and question-processing failures also create `FAILED` search logs and failed traces |
| Runtime Contract | `verify-runtime.ps1` respects `.env`'s `SERVER_PORT` and checks health, admin status, `/api/ask`, `/api/v1/ask`, and forbidden copy |
| Runtime Preflight | `preflight.ps1` checks provider/env/safety settings and key numeric settings before startup |
| Local Verification | `verify-local.ps1` combines server-free preflight, script parsing, JS syntax checks, and Maven tests with incremental compilation disabled |
| Repository Text Safety | Reject corrupted Korean encoding patterns in documentation, scripts, and Java source/tests |
| Runtime Evidence | `verify-runtime.ps1` writes key JSON responses and `runtime-summary.json` under `target/runtime-evidence/` |
| Evidence Report | `export-evidence-report.ps1` combines runtime/scenario summaries into `target/evidence-report.md`, excluding API keys and full questions |

## Second-Stage Answer Quality Metrics

| Metric | Description |
| --- | --- |
| Critic Status | Status after `CriticAgent` review must match the expectation |
| Korean Visible Text | Reasoning and follow-up questions must not appear as English-dominant sentences |
| Forbidden Copy | Block portfolio/demo wording: demo, sample, 샘플, 데모, 미니 프로젝트 |
| Decisive Legal Phrase | Block definitive phrases such as 문제없습니다, 합법입니다, 위법입니다 |
| Min Cited Articles | OK or LOW_CONFIDENCE answers must preserve citations |
| Valid Article Numbers | At least one article number specified in the set must occur in citedArticles |
| Reasoning Article Numbers | Article numbers in reasoning must stay within citedArticles/expected article numbers |
| Markdown Marker Limit | Limit excessive emphasis markup generated by the LLM |

## Baseline Questions

```json
[
  {
    "question": "기술자료를 해외 법인에 제공해도 되나요?",
    "expectedStatus": "OK",
    "minCitedArticles": 1,
    "minVectorHits": 1,
    "expectedCitations": [
      {"lawTitle": "방위사업법", "articleNumber": "제57조"}
    ]
  },
  {
    "question": "이거 해도 돼?",
    "expectedStatus": "INSUFFICIENT_INFO"
  },
  {
    "question": "대외무역법 시행일은 언제인가요?",
    "expectedStatus": "OK"
  },
  {
    "question": "대외무역법 제19조의2는 이전과 어떻게 바뀌었나요?",
    "expectedStatus": "OK"
  }
]
```

The actual fixed set is `harness/questions.json`, currently containing 12 questions. It prioritizes trade-security, defense, and technology-protection questions verifiable against the Spring seed corpus.

## Current Files

```text
harness/questions.json
harness/answer-quality-v2.json
```

Current automated tests:

```text
src/test/java/com/example/lawassistant/eval/EvaluationHarnessTest.java
src/test/java/com/example/lawassistant/eval/AnswerQualityHarnessTest.java
src/test/java/com/example/lawassistant/docs/RepositoryTextSafetyTest.java
src/test/java/com/example/lawassistant/docs/EnvironmentConfigurationContractTest.java
```

Checks:

- HTTP 200 API response
- Expected `status`
- Minimum `citedArticles` count
- Minimum `vectorHits` for normal questions
- At least one expected law/article pair in citations
- Domain recall cases for tanks/defense materials, strategic goods classification, and export declarations under 관세법
- `questionType` routing and citation preservation for metadata/revision-comparison questions
- Minimum `historicalEntries` count for previous revisions within comparison citations
- No article numbers introduced in answer text outside the cited list
- Lexical ranking prioritizes accurate candidates when law titles/article numbers are explicit
- Spacing variants and practical aliases expand into canonical law-title search terms
- `verify-runtime.ps1` preserves `/healthz`, `/api/v1/health`, `/api/v1/ask`, `/api/v1/admin/status`, and optional `/api/v1/admin/reindex` contracts
- Tests require runtime evidence JSON and summaries from `verify-runtime.ps1`
- Tests require `preflight.ps1` checks for OpenRouter/Cohere/Qdrant configuration, ports/numbers, and sensitive-information log flags
- `EnvironmentConfigurationContractTest` verifies that env names used in `application.yml`, `docker-compose.yml`, and `preflight.ps1` are documented in `.env.example`
- A non-JSON-object OpenRouter chat response produces a format failure without exposing raw text; AnswerWriter retries once and propagates repeated failure
- `verify-local.ps1` runs server-independent verification together and leaves runtime verification separate
- `export-evidence-report.ps1` produces a submission-ready Markdown report from runtime/scenario summaries without secrets or full questions
- `RepositoryTextSafetyTest` blocks corrupted Korean encoding patterns in docs, scripts, Java source/tests, and harness files

## Verification by Change Type

| Change type | Minimum verification |
| --- | --- |
| Answer generation, citations, status policy | `AskResponseInvariantTest`, `EvaluationHarnessTest` |
| Question analysis, query generation, retrieval | `EvaluationHarnessTest` plus relevant questions |
| Candidate scoring, reranker preprocessing | `RetrievalAgentRerankerTest`, `EvaluationHarnessTest` |
| Controller/API contract | `AskControllerIntegrationTest` or `AdminControllerIntegrationTest` |
| LLM/Embedding/Vector/Reranker provider | `ProviderInterfaceTest`, `OpenRouterChatModelClientTest`, `AnswerWriterAgentTest` |
| Search log or agent trace | `AdminControllerIntegrationTest` |
| Failure audit path | `AskOrchestratorServiceFailureTest` |
| Runtime verification scripts | `ScenarioScriptContractTest` |
| Provider/env preflight | `ScenarioScriptContractTest` |
| Local verification wrapper | `ScenarioScriptContractTest`, `scripts/verify-local.ps1` |
| Evidence report output | `ScenarioScriptContractTest`, `scripts/export-evidence-report.ps1` |
| Changes spanning multiple agents | `mvn test` |

For answer-quality policy changes alone, run at least:

```bash
mvn -Dtest=AnswerQualityHarnessTest,CriticAgentTest,AnswerWriterAgentTest test
```

## Question Set Maintenance Rules

- Add a fixed question to `harness/questions.json` whenever user-visible answer behavior changes.
- Set `minCitedArticles` to at least 1 for `status=OK` cases.
- Where possible, specify law titles and article numbers in `expectedCitations` for `status=OK` cases.
- Set `minHistoricalEntries` to at least 1 for revision-comparison cases.
- Retain `INSUFFICIENT_INFO` cases for ambiguous questions, insufficient facts, and missing evidence.
- Maintain the set using Korean questions.
- The v2 quality set uses evaluation reasoning and article numbers, not real company data.
- Do not include real company names, internal URLs, accounts, API keys, or nonpublic case information.
- Give each question one regression purpose.

## Completion Criteria

When reporting completion, state one of the following:

- Test commands run and their results
- Tests not run and why
- For documentation-only changes, at least the assessment that the scope does not alter code behavior

For working directories configured with a real database, first follow the [test isolation procedure in the runbook](runbook.md). Automatic isolation of the default test command is not yet guaranteed.

Recommended full verification in an isolated development environment:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1
```
