# C4 Architecture Overview

[한국어](../../ko/architecture/c4.md) | [English](../../en/architecture/c4.md)

This document describes the implemented structure from a C4 perspective. It reflects actual code and execution flows, not a future target architecture.

## Level 1 — System Context

```mermaid
C4Context
    title Law Research Assistant System Context

    Person(researcher, "Research user", "Checks legal evidence and submits questions.")
    System(app, "Law Research Assistant", "Provides limited-scope research results with cited articles.")
    System_Ext(legalize, "legalize-kr", "Source repository of Korean laws in Markdown.")
    System_Ext(provider, "Optional AI provider", "Used for summarization and wording when configured.")

    Rel(researcher, app, "Submits questions and reviews results")
    Rel(app, legalize, "Synchronizes and indexes legal sources")
    Rel(app, provider, "Optionally requests generation and embeddings")
```

Users submit questions, and the service retrieves locally indexed legal articles to answer with evidence. AI providers are optional; provider failures or insufficient evidence are not hidden when answering.

## Level 2 — Containers

```mermaid
C4Container
    title Law Research Assistant Containers

    Person(researcher, "Research user")
    System_Boundary(appBoundary, "Law Research Assistant") {
        Container(api, "Spring Boot API", "Java / Spring Boot", "Question API, admin API, input validation")
        Container(orchestration, "Research pipeline", "Java", "Analysis, retrieval, validation, writing, critique, audit logs")
        ContainerDb(database, "Relational database", "H2 or PostgreSQL", "Laws, articles, search logs, agent traces")
        Container(vector, "Vector store", "Qdrant (optional)", "Vectors for semantic retrieval")
        Container(source, "Local legal sources", "Git working tree", "Versioned legal source text in Markdown")
    }

    Rel(researcher, api, "HTTPS/JSON")
    Rel(api, orchestration, "Service calls")
    Rel(orchestration, database, "Reads/writes laws and logs")
    Rel(orchestration, vector, "Optional similarity search")
    Rel(orchestration, source, "Source synchronization and ingestion")
```

H2 can be used in the default development environment; PostgreSQL is used in environments closer to real operation. Qdrant and external AI providers are optional components enabled through configuration.

## Level 3 — Core Request Components

```mermaid
flowchart LR
    controller[AskController]
    orchestrator[AskOrchestratorService]
    analyzer[QueryAnalyzerAgent]
    retrieval[RetrievalAgent]
    validator[EvidenceValidatorAgent]
    writer[AnswerWriterAgent]
    critic[CriticAgent]
    log[SearchLogAgent]

    controller --> orchestrator
    orchestrator --> analyzer
    analyzer --> retrieval
    retrieval --> validator
    validator --> writer
    writer --> critic
    critic --> log
```

Successful request traces retain the following order.

```text
QueryAnalyzerAgent -> RetrievalAgent -> EvidenceValidatorAgent -> AnswerWriterAndCritic
```

`AskController` handles only HTTP requests and responses. Services and agents handle analysis, retrieval, evidence validation, answer writing, critique, and audit logging.

## Core Invariants

- A `status=OK` response must contain at least one `citedArticles` item.
- A `LOW_CONFIDENCE` response with retrieved or hydrated evidence must also contain at least one cited article.
- Do not generate ungrounded law names, article numbers, or legal conclusions.
- Return `INSUFFICIENT_INFO` or follow-up questions when facts are insufficient.
- Answer evidence includes `snapshotVersion`, `indexedAt`, `sourcePath`, and `sourceVersion`.
- The same request has the same `requestId` in response diagnostics, search logs, and agent traces.
