# arc42 — TradeOps Hub

[한국어](arc42.md) · [English](../en/arc42.md)

## 1. 소개와 목표

공개 BIS DPL·EL 파일을 안정적으로 수집하고 원본 추적 정보를 보존하며 한국어 검색·다운로드 업무 화면을 제공한다. 품질 우선순위는 정확한 출처·버전 연결, 안전한 실패 복구, 백엔드 권한 제어, 예측 가능한 검색과 명확한 운영 상태다. 준법 판단을 자동으로 내리지 않는다.

## 2. 제약

회사 코드·데이터 없는 독립 구현이다. 공개 BIS 운영 데이터는 허용하지만 커밋하는 테스트 자료는 가상 데이터다. Java 17/Spring Boot, Next.js/TypeScript, pg_trgm을 사용하는 PostgreSQL과 파일 원본 저장소를 사용한다. API는 단일 인스턴스이며 설정은 환경 변수로 관리한다.

## 3. 범위와 외부 관계

사용자는 수집·검색·내보내기를 수행하고 고정 운영 책임자는 계정·감사·보류 승인을 추가로 관리한다. 외부 의존성은 공식 BIS 안내와 파일 다운로드다. 거래 처리·역할 편집·심사 판정은 제외한다. [제품 범위](product-scope.md)를 참고한다.

## 4. 해결 전략

브라우저 JWT 대신 영속 서버 세션을 사용한다. 매 수집마다 링크를 탐색하고 호스트·파일 구조를 검증하며 원본 행과 정규화 이름을 분리한다. 스냅샷은 원자적으로 반영한다. 페이지·내보내기의 출처 버전을 고정한다. trigram 유사도와 명시적인 한글 사전 확장을 사용하고 후보 유형을 표시한다.

## 5. 구성 요소

[C4](architecture/c4.md)에 실행 구성과 컴포넌트를 설명한다. 컨트롤러는 계정·수집·감사·검색 서비스에 위임하고 저장소가 SQL을 담당한다. 파서·링크 탐색·HTTP는 독립 테스트가 가능하다. PostgreSQL은 세션·감사·업무 상태를 저장하고 원본 바이트는 파일로 보관한다.

## 6. 실행 흐름

- 로그인: CSRF 준비 → 계정 확인·시도 제한 → 세션 ID 교체 → 사용자 인증 상태 저장. 강제 비밀번호 변경 상태에서는 업무 API를 차단한다.
- 수집: 출처 잠금 → 안내 조회 → URL 탐색·검증 → 조건부 GET → 바이트·해시 저장 → 파싱·문제 보관 → 행 비교 → 반영 또는 보류. 실패해도 현재 데이터를 유지한다.
- 검색: 현재 출처 ID를 한 번 확정하거나 지정 ID 수용 → 검색어 정규화 → 이름·별칭·부분·유사 순위 → 동일 원본 행 묶기 → 페이지와 ID 반환. 명시적 검색 요청에서 이력 저장을 선택한다.
- 내보내기: 고정 ID로 검색 반복, CSV 이스케이프·수식 방지, 건수·스냅샷 ID 감사 기록.
- 재시작: 중단 실행을 실패로 표시하고 활성 표시를 지우며 놓친 예약을 한 번 실행한 후 다음 예약 갱신.

## 7. 배포

[운영 안내](runbook.md)를 참고한다. Next.js가 동일 출처 요청을 API로 전달한다. PostgreSQL과 원본 저장소를 함께 백업한다. API 마이그레이션은 순방향으로만 적용한다. 런타임 증거·실제 원본은 Git에서 제외한다. HTTPS 배포에는 Secure 쿠키가 필요하다. 운영 책임자 초기 비밀번호는 최초 생성에만 사용한다.

## 8. 공통 설계 원칙

- 원본 추적: 출처·실행·파일 해시·행 번호·행 해시·출현 순번·생성 시각·검증 결과.
- 식별: 안정적인 BIS 기업 ID를 가정하지 않는다. 이름 변경은 제외·추가로 나타나며 기업을 추론해 합치지 않는다.
- 권한: 백엔드에서 활성 계정을 요구하며 관리 작업은 고정 운영 책임자를 확인한다. 유휴 만료는 30분이고 비밀번호 변경·초기화·비활성화 시 모든 세션을 폐기한다.
- 감사·개인정보: 상관 ID와 제한된 이벤트 메타데이터만 기록한다. 비밀번호·세션 값·검색어는 제외하며 이력은 현재 사용자 범위로 제한한다.
- 실패: 안전한 코드, 성공 버전 불변성, 30% 초과 감소 승인. 파일 구조·필수 이름만 검증하며 날짜·국가 선택 변환 실패는 경고를 만들지 않고 원문을 보존한다.
- 자원 제한: 다운로드 32 MiB, HTTP 시간·리다이렉트·재시도 제한, 검색 페이지 최대 100행. 내보내기는 메모리에 모으며 가져오기에 고정 10,000행 제한은 없다.

## 10. 품질 시나리오

파서 테스트는 따옴표 CSV·여러 줄 값·중복 행·형식 변경·모호한 링크·정규화를 다룬다. PostgreSQL 테스트는 원자적 교체·실패 보존·보류 승인·동시성·재시작·버전 고정·이력 격리·성능을 확인한다. HTTP 시나리오는 세션·CSRF·계정·감사 계약을 검증한다. 브라우저에서는 탐색·검색·상세·다운로드·오류·모바일 동작을 확인해야 하며 빌드만으로 증명되지 않는다.

기록된 로컬 격리 PostgreSQL 측정은 10,000행, 동시 사용자 5명, 검색 100회에서 p95 122 ms, CSV 398 ms다. 장비별 측정치이며 운영 SLA가 아니다. 허용 기준은 p95 <1초, CSV <10초이고 통합 테스트로 재현한다.

## 11. 위험과 기술 부채

BIS 페이지·파일 구조·가용성이 바뀔 수 있으며 추측 대신 확인 가능한 실패로 알린다. 한글 사전 범위는 제한적이다. 분산 작업 임대, DB의 행 불변성 강제 트리거, 보관·삭제 정책과 외부 알림은 없다. 더 큰 자료에서는 CSV 메모리 버퍼와 offset 페이지 처리를 재검토해야 한다. 과거 가상 데이터 도메인 코드는 회귀 테스트용으로만 남아 있고 공개 경로가 없다.

## 12. 용어

DPL: Denied Persons List, 수출권한 거부자 목록. EL: Entity List. 스냅샷: 변경하지 않는 수집 출처 버전. 보류: 검증을 마쳤지만 반영 전 승인을 기다리는 스냅샷. 유사 후보: 이름 유사도 결과이며 기업 동일성이나 법적 판단이 아니다.
