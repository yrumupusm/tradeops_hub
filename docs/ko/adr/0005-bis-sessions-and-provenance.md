# ADR 0005: BIS 수집, 서버 세션과 원본 행 추적

[한국어](0005-bis-sessions-and-provenance.md) · [English](../../en/adr/0005-bis-sessions-and-provenance.md)

상태: 채택, 2026-09-09. 활성 BIS 모듈에서 ADR 0003의 외부 수집 제외, ADR 0004의 역할·JWT 모델, ADR 0002의 안정적인 외부 ID 가정을 대체한다.

## 상황

공개 BIS DPL·EL 파일을 실제로 수집한다. 다운로드 URL과 안내 문구가 바뀔 수 있고 EL의 기업 번호는 비어 있을 수 있다. 같은 이름과 완전히 같은 행도 반복된다. 개인 검색 이력, 철회 가능한 세션과 수집부터 검색까지 연결된 업무 흐름이 필요하다.

## 결정

Spring Session JDBC, HttpOnly 쿠키, CSRF, 30분 유휴 만료와 세션 철회를 사용한다. 운영 책임자는 한 명으로 설정하고 일반 사용자는 같은 업무 권한을 갖는다. 비밀번호 초기화 후에는 변경을 강제한다.

매 실행마다 공식 다운로드 링크를 다시 찾는다. 새 공식 HTTPS URL은 파일 구조 검증 후 받아들인다. 안내·다운로드·최종 URL과 내용 해시를 기록한다. 원본 바이트는 Git에서 제외한 영속 저장소에 보관한다. 일시적 실패의 재시도 횟수를 제한하고 실패 시 기존 현재 데이터를 유지한다.

스냅샷 안의 행은 원본 해시와 출현 순번으로 식별하며 행 번호와 중복을 보존한다. 정규화 이름과 pg_trgm 인덱스를 별도로 사용한다. 이름으로 기업을 합치지 않는다. 출처 전체 버전을 원자적으로 반영하고 30% 초과 감소는 운영 책임자의 승인까지 보류한다. 완료 실행의 집계는 바꾸지 않는다.

다음 주간 예약을 PostgreSQL에 저장한다. 단일 API 스케줄러가 놓친 예약을 한 번 보충 실행한다. 검색 페이지·상세·이력 재실행·CSV는 고정된 스냅샷 ID를 사용한다. 검색 이력은 본인만 볼 수 있으며 운영 책임자도 예외가 아니다. 내보내기는 건수·ID를 감사 기록에 남기며 검색어는 남기지 않는다.

## 결과

이름 변경은 제외·추가로 나타나며 현실의 동일 기업임을 추론하지 않는다. 출처 변경에 따른 실패를 명시한다. API 수평 확장 전 단일 인스턴스 스케줄링을 교체해야 한다. 스냅샷·원본 보관에 저장 공간이 필요하다. 공개 운영 데이터를 커밋하는 테스트 데이터로 사용하지 않는다. 과거 마이그레이션과 테이블은 유지하지만 거래·검토 API는 공개하지 않는다.
