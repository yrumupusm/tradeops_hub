# 현재까지 발견된 문제점

기록일: 2026-09-13. 오늘 서비스를 검토하며 확인한 미해결 항목이다. 아래 개선 방향은 계획이며, 구현 완료를 의미하지 않는다. 기존 운영 제약과 외부 공개 준비는 [작업 목록](../../tasks/todo.md)에서 별도로 관리한다.

## 서비스 개선 항목

### RAG-01 — 긴 조문의 임베딩 입력 제한

- [ ] 개선 및 검증
- 현재 조문을 하나의 검색 단위로 구성하지만, OpenRouter 임베딩 입력은 기본 설정에서 앞부분 4,000자까지만 사용한다. 원문 전체는 DB에 보존된다.
- 뒷부분에만 있는 내용이 벡터 검색에 충분히 반영되지 않을 수 있다. 모든 긴 조문이 실제로 누락된다는 뜻은 아니다.
- 개선 방향: 조문 식별자를 유지한 하위 청크 분할과 검색 결과 통합을 검토한다.
- 완료 기준: 긴 조문 뒷부분에 근거가 있는 질문으로 검색 및 원문 연결을 검증한다. 기존 데이터·벡터를 보존하고 색인 전환과 복구 방법을 마련한다.
- 확인 위치: `OpenRouterEmbeddingClient`의 입력 절단 코드와 `application.yml`의 `app.embedding.max-chars` 설정.

### RAG-02 — 관련성이 낮은 검색 후보 혼입

- [ ] 개선 및 검증
- 검토 당시 실행 환경은 별도 AI 재정렬 모델 없이 검색 점수를 정렬하는 `MockRerankerClient`를 사용했다. 키워드·벡터 검색 및 점수 통합은 구현되어 있다.
- 실제 탱크 수출 질문에서 협의회 관련 조문 등 질문의 직접적인 근거로 보기 어려운 후보가 포함됐다. 별도 재정렬 모델 미사용이 유일한 원인이라고 확정한 것은 아니다.
- 개선 방향: 후보 검색·점수 통합을 평가하고, 필요하면 재정렬 모델을 비교한다.
- 완료 기준: 고정 질문 집합에서 근거 조문 검색 품질을 전후 비교하고 지연·비용도 확인한다. 모델 연결만으로 완료 처리하지 않는다.

### RAG-03 — 인용이 있어도 답변 해석·누락 위험 존재

- [ ] 안내 및 품질 검증 보완
- 인용 조건과 일부 표현 검사가 법령 해석의 정확성이나 필요한 조건의 완전성을 보장하지 않는다.
- 개선 방향: 원문 확인과 사람의 최종 판단 안내를 유지하고, 근거와 답변의 일치 여부·필수 조건 누락을 평가한다.
- 완료 기준: 잘못된 근거 연결과 조건 누락 사례를 평가에 포함한다. 위험이 완전히 제거됐다고 표현하지 않는다.

### RAG-04 — 프로젝트 수준의 체계적인 품질 평가 부족

- [ ] 평가 집합 및 비교 절차 마련
- 실제 검색 동작은 확인했지만, 이번 검토에서 정답·필수 근거를 갖춘 고정 평가 집합과 검색·답변 품질 측정 결과는 확인되지 않았다. 기능 테스트 통과나 응답 상태 `OK`는 답변 정확성 검증과 다르다.
- 개선 방향: 대표 질문, 기대 근거 조문, 답변 필수 요소, 판단 기준을 정하고 현재 결과를 기준선으로 기록한다.
- 완료 기준: 모델·검색 설정·자료 기준 시점을 기록한 재현 가능한 평가와 실패 사례 검토가 가능하다. 모델 간 성능 우위는 비교 없이 주장하지 않는다.

### SEARCH-01 — 일반적인 영문 약어 확장 검색 미구현

- [ ] 필요 범위 정의 및 구현·검증
- 등록된 원본 이름·별칭 검색은 지원하지만, 별칭이 없어도 `Ltd`와 `Limited`, `Inc`와 `Incorporated`를 자동으로 같은 표기로 취급하는 일반 규칙은 구현되어 있지 않다.
- 개선 방향: 검색 전용 약어 규칙의 범위를 정의한다. 원본 이름을 변경하거나 이름만으로 기업을 병합하지 않는다. `Co`와 `Corp`를 같은 약어로 취급하지 않는다.
- 완료 기준: 등록 별칭이 없는 가상 사례에서 검색을 검증하고, 무관한 이름의 오탐 증가도 확인한다.

## 처리 순서와 기록

우선 RAG-04 평가 기준선을 마련한 뒤 RAG-01·RAG-02·RAG-03 개선 효과를 확인한다. SEARCH-01은 별도 작업으로 진행할 수 있다. 항목 완료 시 해당 체크박스와 함께 변경 커밋, 검증 내용, 남은 제약을 한글·영문 문서에 기록한다.
