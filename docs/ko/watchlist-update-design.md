# BIS 수집·검색 설계

[한국어](watchlist-update-design.md) · [English](../en/watchlist-update-design.md)

현재 설계는 [ADR 0005](adr/0005-bis-sessions-and-provenance.md), [API 계약](api-contract.md), [제품 범위](product-scope.md)에 정리한다.

```text
주간 예약 또는 수동 요청
  → 출처 잠금 / RUNNING 실행 생성
  → 안내 페이지 → 해당 문단 링크 → 공식 HTTPS 검증
  → 조건부 다운로드 → 원본 바이트와 해시 보관
  → 파일 구조·행 검증 → 원본 스냅샷과 정규화 검색 이름 저장
  → 현재 스냅샷과 원본 행 해시·출현 순번 비교
  → COMPLETED(원자적 반영) 또는 HELD(30% 초과 감소)
  → 버전 고정 검색 → 상세 / CSV

어느 단계든 실패하면 FAILED와 안전한 오류 코드를 기록하고 기존 현재 버전을 유지
```

DPL TXT는 따옴표를 사용하는 쉼표 구분 데이터이고 EL은 CSV다. 원본 필드와 검색·변환 값을 별도로 보존한다. 열 순서 변경과 추가 열은 허용하지만 필수 헤더 누락은 실패한다. 빈 이름이 있으면 반영하지 않는다. 검증은 파일 구조와 필수 이름만 다루며, 선택적 날짜·국가 변환 실패는 검증 문제를 만들지 않는다. 원문은 보존하고 완전히 같은 행에도 출현 순번을 부여한다.

파일 바이트 해시는 스냅샷 재사용에 사용한다. 행 해시는 CSV 서식과 필드 순서를 무시하지만 필드 값은 유지한다. 이름 변경만으로 동일 기업임을 판단할 수 없으므로 차이는 추가·제외 행으로 표시한다. 출처 URL 이력은 파일·데이터 변경과 독립적으로 기록한다.

매번 안내 페이지의 다운로드 링크를 다시 찾는다. 허용 공식 호스트는 `bis.gov,www.bis.gov,media.bis.gov`다. 안내 페이지 이동은 허용 호스트 안에서 리다이렉트되거나 설정을 변경해야 한다. 문구·마크업 변경으로 링크가 모호하면 추측하지 않고 실패로 남겨 담당자가 확인하게 한다.
