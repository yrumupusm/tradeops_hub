# C4 모델

기준일: 2026-09-08. 현재 코드의 시스템 경계와 의존성을 설명합니다. 각 도식은 C4의 맥락·컨테이너·컴포넌트 관점을 Mermaid로 표현했습니다. 서비스 클래스는 API 프로세스 내부 컴포넌트입니다.

## 1. 시스템 맥락

```mermaid
flowchart LR
    Operator[운영자 / 관리자]
    Viewer[조회자]
    Hub[TradeOps Hub<br/>목록 갱신 · 변경 검토 · 거래 데이터 관리]
    Operator -->|갱신 실행 · CSV 업로드 · 결과 확인| Hub
    Viewer -->|현재 목록 · 변경 · 실행 이력 조회| Hub
```

현재 원본은 애플리케이션에 포함된 가상 데이터입니다. 외부 공급자, 자동 수집 작업, 자동 매칭 엔진은 연결되어 있지 않습니다. 검토 API는 호출자가 전달한 점수와 처분을 기록하며, 점수를 계산하거나 법적 결론을 내리지 않습니다. 검토 API의 조회자 쓰기 차단은 [미완료 항목](../arc42.md#11-위험과-기술-부채)입니다.

## 2. 컨테이너

```mermaid
flowchart TB
    Browser[사용자 브라우저<br/>React 화면 · 메모리 내 Bearer 토큰]
    subgraph System[TradeOps Hub]
        Web[웹 서버<br/>Next.js / TypeScript · 기본 3000]
        subgraph Backend[API 프로세스 · 기본 8081]
            API[Spring Boot / Java 17<br/>인증 · 검증 · 업무 처리]
            Fixtures[클래스패스 리소스<br/>가상 XML / CSV 버전 A · B]
        end
        DB[(PostgreSQL 16<br/>사용자 · 실행 · 스냅샷 · 거래 · 검토)]
    end
    Browser -->|페이지와 정적 리소스 요청| Web
    Browser -->|HTTP / JSON · multipart · Bearer| API
    API -->|JPA 및 JDBC| DB
    API -->|파일 읽기| Fixtures
```

웹 서버가 API 요청을 중계하지 않습니다. `page.tsx`의 클라이언트 코드가 API를 직접 호출하며, 허용 origin은 기본 `http://localhost:3000`입니다. Docker Compose는 PostgreSQL만 실행합니다. API와 웹은 별도 프로세스이며 H2는 백엔드 테스트에서 사용합니다. TLS 종단, 메시지 큐, 별도 검색 서버는 현재 구성에 없습니다.

## 3. API 컴포넌트

```mermaid
flowchart TB
    HTTP[HTTP 요청] --> Correlation[CorrelationIdFilter]
    Correlation --> Security[SecurityConfig / JwtAuthenticationFilter]
    subgraph API[Spring Boot API 내부]
        Auth[AuthController / AuthService / JwtService]
        Watch[WatchlistRunController]
        Update[WatchlistUpdateService]
        Read[WatchlistReadService]
        Source[FictionalWatchlistSource]
        Parsers[XmlWatchlistPayloadParser / CsvWatchlistPayloadParser]
        Compare[WatchlistComparator]
        Repos[Watchlist JPA repositories]
        Import[TransactionImportController / TransactionImportService]
        Query[TransactionQueryController / TransactionQueryService]
        Review[ScreeningReviewController]
        Users[UserRepository]
        JDBC[JdbcTemplate]
    end
    DB[(PostgreSQL)]
    Security --> Auth
    Security --> Watch
    Security --> Import
    Security --> Query
    Security --> Review
    Auth --> Users --> DB
    Watch --> Update
    Watch --> Read
    Update --> Source --> Parsers
    Update --> Compare
    Update --> Repos
    Read --> Repos --> DB
    Import --> JDBC
    Query --> JDBC
    Review --> JDBC --> DB
```

목록 갱신은 `WatchlistUpdateService.run()`의 트랜잭션에서 실행·스냅샷·행·변경 기록을 저장합니다. 현재 목록은 별도 테이블을 덮어쓰지 않고 해당 공급자의 가장 큰 스냅샷 ID를 조회합니다. 변경 조회도 최신 스냅샷을 기준으로 합니다.

거래 가져오기와 검색은 서비스에서 `JdbcTemplate`을 직접 사용합니다. 검토 기록은 아직 컨트롤러에서 두 번의 SQL 쓰기를 실행합니다. 서비스·저장소 분리와 검토/감사의 원자적 저장은 목표 구조이며, 이 도식은 현재의 직접 의존성을 표시합니다.
