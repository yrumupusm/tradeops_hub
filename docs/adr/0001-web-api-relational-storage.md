# ADR 0001: 웹·API 분리와 관계형 데이터 저장

**상태:** 채택 · **기록일:** 2026-09-08

## 상황

목록 갱신 화면과 거래 데이터 API가 동일한 사용자, 실행 이력, 스냅샷을 사용합니다. 데이터의 참조 관계와 저장 순서를 관리하면서 화면과 업무 규칙을 각각 변경할 수 있어야 합니다.

## 대안

- Next.js 서버에서 업무 로직까지 처리하면 프로세스 수는 줄지만 웹과 업무 계층의 변경이 결합됩니다.
- 업무마다 서비스를 분리하면 독립 배포가 가능하지만 현재 규모에서는 분산 트랜잭션과 운영 비용이 커집니다.
- 문서 저장소는 유연하지만 실행·스냅샷·행의 참조 무결성을 별도로 관리해야 합니다.

## 결정

Next.js는 화면을 제공하고 Spring Boot API 하나가 인증·검증·업무 처리를 담당합니다. PostgreSQL을 영속 저장소로 사용하고 Flyway로 스키마를 관리합니다. 현재 목록 저장은 JPA, 거래 가져오기·조회와 검토 기록은 JDBC를 사용합니다. H2는 서버 없이 실행하는 통합 테스트에 사용합니다.

## 결과

목록 갱신의 여러 쓰기를 하나의 데이터베이스 트랜잭션으로 묶을 수 있습니다. 브라우저가 API를 직접 호출하므로 API 주소와 CORS 설정을 함께 관리해야 합니다. API 내부의 JDBC 접근을 저장소 계층으로 모으는 작업이 남아 있습니다.

H2 테스트 통과만으로 PostgreSQL 호환성을 판단하지 않습니다. 현재 `TransactionQueryService.monthly()`의 `formatdatetime` 쿼리는 H2에 의존하며 PostgreSQL 실행 전에 보완해야 합니다.
