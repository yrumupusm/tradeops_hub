# 문서 언어와 한국어 화면 기준

[한국어](../ko/documentation-language.md) | [English](../en/documentation-language.md)

이 서비스는 모노레포의 [작업 지침](../../../../AGENTS.md)과 [프로젝트 안내](../../../../PROJECT_GUIDE.md)를 따른다. 한국어 공개 문서와 영어 구현 참고 문서는 하나의 설계를 설명하며 함께 갱신한다.

## 문서 구성

| 구분 | 기준 |
| --- | --- |
| 공개 README | 한국어 서비스 소개·실행·검증·구조·문서 안내 |
| 공개 설명 문서 | `docs/ko/`를 기본으로 연결 |
| 구현·검증 참고 문서 | `docs/en/` 우선 참고 |
| 작업 지침 | `AGENTS.md`, `PROJECT_GUIDE.md`는 영어 유지; 공개 문서의 번역 쌍이 아님 |
| 문서 대응 | `docs/ko/<path>`와 `docs/en/<path>`에 같은 상대 파일명 사용 |
| 문서 입구 | [전체 문서 목록](../README.md)에서 언어별 문서 쌍 연결 |
| 변경 관리 | 설계·API·운영 변경은 두 언어 문서를 같은 커밋에서 갱신 |

TradeOps Hub의 `tasks/todo.md`도 영어 작업 상태 문서입니다. 이 저장소에 같은 파일이나 새 작업 관리 체계를 만드는 것은 이번 번역의 범위가 아닙니다. 루트 `handoff.md`는 기존 작업 이력이며 공개 설계 문서와 구분해 보존합니다.

## 두 언어의 일치 규칙

- 두 언어는 같은 설계와 구현 상태를 설명합니다. 언어별로 다른 설계를 관리하지 않습니다.
- 제약, 예시, 완료 여부, 과거 ADR의 결정 맥락을 번역에서도 유지합니다.
- 페이지를 추가하거나 삭제할 때 양쪽에 함께 반영하고 전체 문서 목록을 갱신합니다.
- 코드·계약·운영 절차가 바뀌면 관련 한국어와 영어 문서를 같은 커밋에서 수정합니다.
- 내용이 다르면 코드, 테스트, 사용자의 최신 승인 요구사항을 확인해 두 문서를 함께 고칩니다. 영어 작업 문서가 사용자 의도보다 우선하지 않습니다.
- 제안한 기능은 구현 완료처럼 쓰지 않습니다. TradeOps 연동 인계의 과거 기준 커밋·관찰 건수·미구현 항목을 유지합니다.
- 상대 경로와 반대 언어 링크를 함께 점검합니다. 기존 루트 문서 경로는 이전 안내만 남기고 본문은 언어별 경로에서 관리합니다.

## 한국어 화면 규칙

- 메뉴, 입력 안내, 오류, 알림, CSV 제목은 자연스러운 한국어로 씁니다.
- 날짜·숫자는 한국어 사용자가 읽기 쉬운 형식으로 표시하고 시간대(예: `Asia/Seoul`)를 명확히 합니다.
- 코드 식별자, API 경로, 설정 변수 이름, C4·ADR 같은 표준 명칭은 원형을 유지합니다.
- 법령명·조문 번호·원문 내용 등 원본 이름과 데이터를 보존합니다. 원본 레코드를 자동 번역하거나 임의로 다듬지 않습니다.
- 영어 문서에도 실제 한국어 UI 문구와 평가 질문, 원문 형식 예시를 그대로 인용할 수 있습니다. 문서를 영어로 쓴다고 화면도 영어로 바꾸지 않습니다.
- 상태 코드의 한국어 표시와 법령 원문의 수정은 다른 작업입니다.

## 적용 범위와 검증

공개 설계·API·운영·평가·연동 문서와 ADR 전체를 `docs/ko/`와 `docs/en/`의 대응 페이지로 관리합니다. 루트 README는 한국어 문서로 안내하며, 작업 지침과 검증 스크립트는 영어 문서를 참조합니다. 실행 명령은 별도 설명이 없으면 프로젝트 루트 기준입니다.

문서 검증은 페이지 대응, 언어 전환 링크, 로컬 링크, 예시 코드 블록의 대응, 깨진 한국어 인코딩, 기존 지침·검증 스크립트 계약을 확인합니다. 자동 검사는 의미상 번역 일치까지 보장하지 않으므로 제약과 구현 상태는 두 문서를 직접 대조합니다. 이 구조 변경 자체는 API·검색·임베딩 동작을 바꾸지 않습니다.
